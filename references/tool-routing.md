# 跨 AI 工具路由

本文件用于让同一套业务 Skill 在不同 AI 环境中执行。先盘点当前环境实际可用的工具，再选择对应路径；不要因为示例中出现某个工具名就假设它一定存在。

## 一、能力检查

开始前确认以下能力：

1. 能否读取飞书 Docx 的正文、区块和内嵌资源。
2. 能否读取文档批注、回复链、审阅人身份和解决状态。
3. 能否复制文档或创建新文档，并在指定文件夹内写入内容。
4. 能否读取本地 xlsx、docx、PDF，运行 Python 脚本并生成图片/PDF。

缺少某项能力时，只向用户申请完成该步骤所必需的权限、文件或连接，不扩大操作范围。

## 二、飞书文档路径

按以下优先级选择：

1. **当前 AI 的原生飞书连接器/工具**：使用其文档读取、评论、云盘复制和文档创建能力。
2. **已安装且已认证的 lark-cli**：先读取本机对应版本的 lark-doc/lark-drive 使用说明，再调用命令；不要照搬可能过期的命令参数。
3. **飞书 OpenAPI**：仅在具备合法凭据和相应权限时使用。读取批注可从 `GET /open-apis/drive/v1/files/{file_token}/comments` 开始，`file_type=docx`，处理分页，并读取 replies、user_id、is_solved 等字段。
4. **无可用飞书能力**：请用户导出 docx 或提供批注导出结果；仍然只在本地副本上修订。

## 三、批注修订流程

1. 读取正文、全部批注及回复链，处理分页。
2. 将审阅人标识解析为姓名；同名或身份不确定时先核验，不凭文本猜测。
3. 仅筛选用户指定审阅人的批注。已解决批注也要读取，但除非回复链显示仍需处理，否则不要重复修改。
4. 建立“批注原文 → 对应正文 → 拟修改内容 → 处理状态”清单。
5. 复制原文档或新建文档；绝不覆盖原文档。
6. 在副本中落实批注，保留未被批注要求改变的结构、数字、图片和格式。
7. 回读新文档，逐条核对批注清单，并向用户交付新文档链接和未处理项。

## 四、本地文件与脚本

- 从本 `SKILL.md` 所在目录解析 `scripts/`、`references/` 和 `assets/`。
- 使用 `python3 scripts/profit_analysis.py ...` 统计盈利；输入文件只读。
- 使用 `python3 scripts/dist_chart.py` 做样式冒烟测试，或作为模块调用 `draw_dist`。
- 使用 `python3 scripts/make_report_pdf.py 输入.md 输出.pdf` 生成 PDF；可用 `--assets-dir`、`--image-dir` 覆盖默认资源目录。
- 如缺少 Python 依赖，安装 `requirements.txt` 中列出的库，或请用户在受控环境中安装。

## 五、交付检查

- 原始文档未被修改。
- 新文档标题能够区分“修订稿/清洁版/风测版本”。
- 目标审阅人的每条批注都有明确处理状态。
- 盈利数据、统计日期、产品名、图表分档与正文一致。
- 公开版完成业绩与客户盈利数字脱敏。
- PDF 字体、Logo、目录、水印、页码和图片均可正常显示。
